# Audit antislop 002 — 2026-09-30 — frontend React SMM Panel

Design Read (terkunci dari audit-001): ops console untuk solo operator, flat-dark, bahasa operator Indonesia, dial ENERGY 2 / RHYTHM 2 / MOTION 2.
Scope: `frontend/src` (21 rute) + runtime aksesibilitas. Metode: render live di http://localhost:5175 (Chromium), uji keyboard tombol sungguhan, build produksi + oxlint, simulasi fetch gagal via `window.fetch` override.
Mode: `during` (preferensi global). Laporan ini merangkum sesi perbaikan besar (kinetics + R-03 + R-27 + retry interaktif + copywriting) dan hasil uji aksesibilitas keyboard.

## Ringkasan perbaikan sesi (HIGH, Hard Gate)

1. R-02: 44 em dash di teks UI dibersihkan lintas 9 halaman (Accounts, AutoCreate, Backup, Captcha, Engagement, Farm, Fleet, Proxy, Tiktok). Placeholder proxy kosong diganti "belum ada IP". Verifikasi grep: 0 em dash tersisa di teks UI (sisa hanya di komentar kode, yang dikecualikan aturan).
2. R-03: sweep overflow 21 rute pada lebar 320px dan 1280px, semua hasil 0. Perbaikan: grid statistik FB 2x2 (<=720px), kontainer scroll untuk tabel (FbDashboard, Monitoring, Captcha, Notifications), `.grid2` minmax(0,1fr), Sparkline responsif, `.pc-metrics` overflow-wrap, `.acc-hero` flex-wrap, `.ai-tabs` wrap. Target sentuh >= 44px dipertahankan (nav, tombol).
3. R-27: loading spinner + empty state di Fleet, Notifications, Captcha, Likes (bug "empty state saat masih loading" diperbaiki). Loading + keyframes spin dikonsolidasi ke ui.css.
4. R-27/kejujuran error: banner retry interaktif di 6 halaman (Notifications, Captcha, Fleet, Monitoring, History, Likes). Pola: counter attempt + flag failed + tombol "Coba lagi" + pesan "Gagal memuat ..., lalu coba lagi". Terverifikasi live 6/6 dengan fetch diblokir. Bug History tanpa `.catch()` (unhandled rejection) diperbaiki. Catatan: `api()` tidak pernah throw pada error HTTP, jadi deteksi gagal harus cek `r && !r.error` selain `.catch()`.
5. R-32: uji keyboard menyeluruh (bagian khusus di bawah). Dua bug ditemukan dan diperbaiki: modal React tanpa focus trap, dan dialog kustom tidak mengembalikan fokus.

## Perbaikan copywriting sesi (MEDIUM, Purpose-Gate)

## Uji aksesibilitas keyboard (R-32, sesi ini)

Metode: navigasi Tab dengan tombol keyboard sungguhan via jembatan browser (bukan programmatic focus), Enter untuk aktivasi, Escape untuk menutup dialog. Halaman uji: /akun (tabel + 3 modal + dialog kustom), /engagement (3 tab + form), /history (filter).

TEMUAN (sebelum perbaikan):

1. HIGH (R-32): modal React (`.overlay` di Accounts x3: Tambah Akun, Proxy/Session, Riwayat IP; dan Likes x1) tidak memindahkan fokus ke dalam modal saat dibuka. Pengguna keyboard tetap berada di tombol pemicu di belakang overlay, Tab berjalan di halaman yang tertutup.
2. HIGH (R-32): focus trap global hanya mengenali `.dlg-ov` (dialog kustom), tidak mengenali modal React. Tab keluar dari modal ke elemen belakang (terbukti: fokus lompat ke "Semua (55)").
3. MEDIUM (R-32): dialog kustom `confirmDlg`/`alertDlg` tidak mengembalikan fokus ke elemen pemicu setelah ditutup (fokus jatuh ke body).

PERBAIKAN:

4. `kinetics.js`: focus trap diperluas ke `.dlg-ov` DAN `.overlay`; saat modal muncul, MutationObserver memindahkan fokus ke elemen pertama di modal dan menyimpan pemicu; saat modal tertutup, fokus dikembalikan ke pemicu.
5. `dialog.js`: `build()` kini menyimpan `document.activeElement` sebelum overlay dibuat dan memanggil `prevFocus.focus()` saat dialog selesai ditutup (termasuk jalur timer fallback animasi keluar).

HASIL (setelah perbaikan, semua PASS):

6. Tab order /akun: bersih, hanya kontrol nyata (nav -> hero -> tombol -> tab -> cari -> filter -> tabel -> paginasi), tanpa stop tersembunyi.
7. Enter pada "+ Tambah Akun" membuka modal; fokus otomatis masuk ke input pertama modal (terverifikasi `activeElement` INPUT di dalam `.overlay`).
8. Tab 7x di modal Tambah Akun: fokus berputar di dalam modal (input nama, email, password, platform, Batal, Simpan), tidak pernah keluar ke halaman belakang.
9. Escape menutup modal React dan fokus kembali ke "+ Tambah Akun".
10. Enter pada tombol "Hapus" membuka dialog kustom; fokus masuk ke tombol "Ya, hapus"; Tab berputar ok/cancel di dalam dialog; Escape membatalkan, dialog tertutup, fokus kembali ke tombol "Hapus" (aksi destruktif tidak terjadi).
11. Tab + Enter di /engagement: tombol tab Komentar/Pesan Langsung/Story dapat difokus dan mengganti panel; dropdown akun native tetap bekerja dengan keyboard.
12. Tab + Enter di /history: tombol filter (Posting & Login, Engagement, Semua akun) berfungsi; select filter menerima fokus; tidak ada modal terbuka, tidak ada jebakan fokus.

## Rekap kinetics sesi ini (Purpose-Gate, alasan tertulis per R-31)

- Toast Overshoot (kurva spring `cubic-bezier(.18,1.25,.4,1)` 0.55s): umpan balik hasil aksi; sampel transform terverifikasi (264->80->23->1.6->-4.1->-5.2->...->0) dan dijaga `prefers-reduced-motion`.
- Push Button (translateY 1px 0.06s, semua tombol): konfirmasi tekan terasa di seluruh panel tanpa mengubah layout.
- Tab Pill Glide (`cubic-bezier(0.65,0,0.35,1)` 0.4s, komponen SegTabs menggantikan 6 pemakaian `.seg` di 5 halaman): arah perpindahan filter terbaca; aksen via var `--kin-seg-accent` (FB #1877F2).
- Modal spring masuk + keluar animasi + Tab focus trap (`.dlg.in` dipasang bersama overlay; kurva `cubic-bezier(.34,1.56,.64,1)` 0.5s): dialog terasa hidup, aksesibilitas tidak dikorbankan.
- Semua motion di belakang `prefers-reduced-motion`.
