# AUDIT UI — Frontend React SMM Panel (19 Sep 2026)

> Lingkup: 17 route / 15 file halaman + Dashboard + Layout (~2.400 baris JSX + 9 CSS).
> Metode: baca seluruh source, silang-cekap endpoint frontend vs server.js (145 route),
> build produksi `vite build` (SUKSES, 57 modul, 340KB js / 26KB css, 1,74s).

---

## VERDICT

Fondasi UI **di atas rata-rata**: bahasa visual konsisten (dark, gradien brand per
platform), empty-state informatif, konfirmasi untuk aksi destruktif, polling dengan
interval wajar, drawer HP + hamburger. Tapi ada **2 halaman mati (stub JSON dump)**,
**4 area fitur backend yang belum punya UI sama sekali**, dan beberapa kebocoran UX
kecil. Build hijau, nol error kompilasi.

## 1. PETA KONDISI PER HALAMAN

### ✅ Matang (siap pakai)
- **Dashboard** — hero salam, 4 stat count-up, kartu platform, antrean hari ini,
  aktivitas live dengan highlight item baru, poll 10s/30s berlapis. Paling rapi.
- **Accounts** — tab Aktif/Semua/Mati dengan hitungan, search, pagination, modal
  tambah (ESC ditangani), aksi Buka/Login/Hapus per status. 
- **Posting** — dua mode platform dengan perbedaan yang benar (IG wajib media +
  pratinjau live; FB jadwal + repeat + daftar jadwal + hapus), AI fill, progres
  step-bar. Pratinjau IG langsung mengikuti caption/file — detail bagus.
- **Farm** — dual mode (kendali 1 HP / grid semua HP), tap & swipe dengan konversi
  koordinat 1080x2340, mirror ke semua HP, tombol fisik, scrcpy, baterai, refresh
  5s + grid 10s. Sesuai spesifikasi dokumen sistem.
- **AutoCreate** — panel jalankan dengan proxy pilih/tempel-sekali-pakai, timer,
  log live, cooldown 24 jam via confirm, pill status, langkah panduan + perintah
  CLI yang bisa disalin. Note realistis per platform (FB diblokir Meta).
- **Warming** — hero status HIDUP/MATI + slot berikutnya, jadwal jam ganda,
  persenjataan berkonfirmasi, laporan terakhir, tabel progres + Setujui/Stop.
  Gerbang 14 hari tampil jujur (hari X/Y).
- **Monitoring** — panel layanan (API/DB/Farm/Antrean), akun aktif dengan bar,
  error 24 jam, kejadian terakhir. Refresh 15s.
- **Proxy** — tambah massal per baris, kredensial dimask (host:port saja), tes
  per proxy dengan hasil ms, assign ke akun. Konsisten dengan aturan 1 akun=1 IP.
- **Likes (FB/IG)** — tabel order + pill status + ringkasan; FB targetLikes
  hard-coded 10 di form (lihat temuan U-3).
- **FbDashboard** — hero biru, 4 stat, tabel akun dengan quick links.
- **History** — filter akun + hasil, 100 terbaru, format waktu id-ID.
- **Backup** — daftar manifest (tipe/ukuran/waktu), buat/restore/hapus dengan
  konfirmasi. Restore TANPA kata peringatan data hilang lebih tegas (lihat U-6).

### ⚠️ Stub (halaman ada, isinya JSON mentah)
- **Captcha.jsx** — menampilkan `JSON.stringify(...).slice(0, 300)`. Bukan UI.
- **Notifications.jsx** — sama, dump JSON mentah 2 kartu.
- **AI.jsx** — setengah jadi: tab caption/hashtag/rewrite/comment bekerja via
  `/api/ai/*`, tapi output tak bisa disalin ke form Posting (alur terputus).
- **Tiktok.jsx** — informasional saja (bukan stub, tapi juga bukan alat).

## 2. TEMUAN

### U-1 [HIGH] Empat fitur backend baru/belum punya UI
Backend kini punya: comment automation, DM automation, story automation, gate
kebijakan (`/api/gate/:id`), rotasi runtime order like — semua tanpa satu pun
elemen UI. Pengguna panel tidak bisa menjalankan/memantau fitur inti konsep
"SMM panel multi-akun" dari panel itu sendiri. Ini gap terbesar antara backend
dan frontend. (Obat: halaman "Engagement" untuk comment/DM/story + kolom alasan
gate di tabel Akun.)

### U-2 [MED] `index.html` memuat `/config.js` lama — lewat Vite proxy saja
`<script src="/config.js">` TIDAK punya `type="module"` → Vite warning saat build
("can't be bundled"). Berfungsi via dev proxy & static :3000, tapi build produksi
(`dist/`) tidak membawa file itu — panel versi build akan kehilangan API key
(`window.__SMM_API_KEY` kosong) bila di-serve dari dist. Obat: inject saat build
(`import.meta.env`) atau fetch runtime dari endpoint.

### U-3 [MED] Likes FB: target likes terkunci 10
`Likes.jsx` mengirim `targetLikes: 10` hard-coded tanpa input. Backend menerima
1-1000. Pengguna tidak bisa menentukan jumlah like order. (IG tidak terdampak —
formatnya per-akun.)

### U-4 [MED] Dashboard: antrean hanya menampilkan jadwal post, bukan order like
Kartu "Antrean Hari Ini" mengambil `/api/schedules` saja. Order like `running`
(bisa berhari-hari) tidak tampak di dashboard — pengguna melihat panel "sepi"
padahal worker sedang menggerus order. (Obat: gabungkan `/api/smm/like-orders`.)

### U-5 [MED] "Status Sistem" dashboard keras-kekode
Tiga baris status ("Dashboard API nyala", "Worker + scheduler nyala") selalu
`b-done` tanpa mengecek apa pun — `/api/workers/status` (endpoint Phase 4) sudah
ada tapi tidak dipakai. Klaim "nyala" bisa bohong saat worker mati — justru
situasi paling penting untuk jujur.

### U-6 [LOW] Restore backup: konfirmasi kurang tegas
`confirm('Restore X? Data sekarang tertimpa.')` cukup, tapi operasi ini
mengganti .env + sessions + DB sekaligus (dan server perlu restart agar sql.js
memuat ulang). Tidak ada peringatan restart → pengguna bisa mengira gagal.

### U-7 [LOW] Scroll horizontal tabel belum global
`.table-wrap { overflow-x: auto }` didefinisikan ulang di Accounts.css dan
Warming.css saja (dengan min-width 560px). Likes/Monitoring/History/FbDashboard/
Proxy/Backup memakai class yang sama tanpa mendefinisikannya — untungnya HTML
table dengan width:100% berperilaku lumayan, tapi kolom sempit di HP belum
dijamin. Pindahkan ke ui.css satu kali.

### U-8 [LOW] `.cut` didefinisikan dobel dengan nilai beda
History.css `max-width:340px`, Posting.css `280px`. Tidak fatal (masing-masing
scoped import), tapi inkonsisten — pindah ke ui.css.

### U-9 [LOW] Layout: link "Semua Akun" tidak pernah "active"
`isActive('/akun')` mengharuskan tanpa query; dari sidebar Operasi, klik
"Semua Akun" → `/akun` → aktif. Tapi setelah memilih platform dari select di
halaman, URL berubah `/akun?platform=fb` → item menu kehilangan highlight
(harusnya grup FB yang menyala). Kecil tapi membingungkan navigasi.

### U-10 [LOW] FbDashboard label tab "Checkpoint" salah makna
Tab ketiga menampilkan "Checkpoint (N)" padahal isinya semua non-aktif
(`status !== 'active'`), termasuk inactive/failed. Label menyesatkan.

### U-11 [INFO] ikon dashboard memakai karakter unicode ('▦', '◷', '▣')
Bedakan dengan Icon SVG di Monitoring — inkonsistensi kecil, tidak mengganggu.

## 3. YANG SUDAH BAGUS (pertahankan)

- **Konsistensi visual**: ui.css sebagai design-system mini (badge/pill/btn/card/
  steps/bar) dipakai lintas halaman; gradien brand FB/IG/TikTok konsisten.
- **Aksesibilitas dasar**: `:focus-visible`, `aria-expanded` pada toggle grup,
  `aria-label` pada input jam & tombol menu, min-height 44px target sentuh.
- **Semantik status tiga bahasa regex** (History/Monitoring/Likes) konsisten
  mengenali status dari DB meski naming backend tidak seragam.
- **Konfirmasi untuk semua aksi destruktif** + ESC menutup modal.
- **Polling disiplin**: interval bervariasi sesuai kebutuhan (farm shot 5s,
  grid 10s, monitoring 15s, dashboard 30s) tanpa websocket — hemat.
- **Anti-slop**: tidak ada gradien berlebihan, tidak ada emoji sebagai ikon
  fungsional, empty-state menawarkan tindakan lanjutan (Buat posting).

   alasan gate di tabel Akun (U-1); ganti "Status Sistem" ke `/api/workers/status`

3. **Struktur**: selesaikan Captcha & Notifications sebagai UI sungguhan atau
   sembunyikan dari sidebar sampai siap; sambungkan output AI → form Posting.
4. **Build**: perbaiki pemuatan API key untuk build produksi (U-2) — penting
   bila suatu saat panel di-serve dari `dist/` alih-alih dev server Vite.
